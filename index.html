Большое саммери по темам контрольной

Ниже — систематизированный конспект по всем темам, которые встречаются в демо-варианте и могут попасться в контрольной. Формат: теория → типовые вопросы → ловушки → примеры.

ТЕМА 1. Где вычисляется арифметика

Теория

  • Арифметические и логические операции выполняет АЛУ (арифметико-логическое устройство) — часть CPU.
  • АЛУ работает с регистрами. Операнды загружаются в регистры, результат кладётся в регистр, обновляются флаги.
  • Память (RAM, SSD, HDD) хранит данные, но не вычисляет.
  • Исходный файл, текстовый редактор, файловая система, сетевой адаптер — к вычислению отношения не имеют.

Типовые вопросы

  • Где вычисляется 7 + 5? → В АЛУ внутри CPU.
  • Что делает АЛУ? → Сложение, вычитание, умножение, деление, AND/OR/XOR/NOT, сдвиги, сравнение.
  • Откуда АЛУ берёт данные? → Из регистров.
  • Куда кладёт результат? → В регистр.
  • Что ещё обновляет? → Флаги (CF, OF, ZF, SF).

Ловушки

  • «В исходном файле» — нет, там только текст.
  • «На SSD» — нет, SSD хранит.
  • «В файловой системе» — нет, это способ организации файлов.

Пример

mov eax, [rbx + 4]   ; загрузка из памяти в регистр
add eax, 5           ; АЛУ: EAX = EAX + 5
mov [rbx + 4], eax   ; запись обратно в память

ТЕМА 2. Адресация массивов

Теория

  • Адрес элемента массива: base + index × sizeof(element).
  • Нумерация с нуля.
  • sizeof(int) = 4 (LP64), sizeof(char) = 1, sizeof(long) = 8, sizeof(pointer) = 8.
  • Little-endian: младший байт по младшему адресу.

Типовые вопросы

  • a[0] по адресу 0x2000, элементы по 4 байта. Адрес a[3]? → 0x2000 + 3×4 = 0x200C.
  • a[0] по адресу 0x1000, элементы по 1 байту. Адрес a[5]? → 0x1005.
  • Массив из 3 int начинается по 0x1000. Адреса элементов? → 0x1000, 0x1004, 0x1008. Размер массива — 12 байт.
  • grade[i][j] в массиве 16×4. Смещение? → 4i + j.

Ловушки

  • Считать по 1 байту вместо размера элемента.
  • Забыть, что нумерация с нуля: a[3] — четвёртый элемент.
  • Путать a+1 (адрес следующего элемента) и a[1] (значение второго элемента).

Пример

int a[5];              // 5 элементов по 4 байта = 20 байт
// a[0] по 0x2000
// a[1] по 0x2004
// a[2] по 0x2008
// a[3] по 0x200C
// a[4] по 0x2010

ТЕМА 3. Файл vs процесс

Теория

  • Файл — последовательность байтов на накопителе. Может не запускаться.
  • Процесс — работающий экземпляр программы. Имеет состояние, ресурсы, PID, адресное пространство.
  • Один файл можно запустить дважды → два процесса с разными PID.
  • После завершения процесса файл остаётся на диске.
  • Завершившийся процесс не получает процессорное время.
  • Новый запуск не обязан получать тот же PID.

Типовые вопросы

  • Что верно о файле и процессе? → Процесс завершился; файл можно запустить снова; файл и процесс — разные сущности.
  • Файл обязательно удалён? → Нет.
  • Процесс продолжает получать CPU? → Нет.
  • Другой запуск получит тот же PID? → Не обязан.

Ловушки

  • «Файл и процесс — одно и то же» — нет.
  • «После завершения файл удаляется» — нет.
  • «PID всегда одинаковый» — нет.

Пример

./program   # процесс 1, PID 1234
./program   # процесс 2, PID 5678
# файл program остался на диске

ТЕМА 4. Стандартные потоки

Теория

  • stdin = 0 — ввод.
  • stdout = 1 — обычный вывод (результат).
  • stderr = 2 — диагностика (ошибки).
  • Перенаправления: < (stdin), > (stdout), 2> (stderr), >> (добавление), | (pipe).
  • stderr не совпадает с stdout автоматически.
  • stdin — не только клавиатура: может быть файл, канал, терминал.
  • stderr не заменяет код завершения.

Типовые вопросы

  • stdin соответствует дескриптору 0? → Да.
  • stderr всегда совпадает с stdout? → Нет.
  • stdin можно перенаправить? → Да.
  • stdout для результата? → Да.
  • stderr заменяет код завершения? → Нет.

Ловушки

  • Путать > и 2>.
  • Думать, что | объединяет stderr.
  • Считать, что stdin — только клавиатура.

Пример

./program < input.txt > output.txt 2> errors.txt
# stdin из input.txt, stdout в output.txt, stderr в errors.txt
./producer | ./consumer
# stdout producer → stdin consumer; stderr не объединяется

ТЕМА 5. Этапы сборки GCC

Теория

Цепочка:

  1. Препроцессор (-E): раскрывает #include, #define. Результат — .i.
  2. Компилятор (-S): переводит C в ассемблер. Результат — .s.
  3. Ассемблер (-c): переводит ассемблер в машинные байты. Результат — .o (объектный файл).
  4. Линковщик: соединяет объектные файлы и библиотеки. Результат — исполняемый файл.

Типовые вопросы

  • Какой этап превращает .c в .s? → Компилятор (компиляция).
  • Какой этап превращает .s в .o? → Ассемблер.
  • Какой этап создаёт исполняемый файл? → Линковщик.
  • Что делает препроцессор? → Раскрывает #include и #define.

Ловушки

  • Путать компилятор и ассемблер.
  • Думать, что gcc — один этап; на самом деле GCC вызывает несколько инструментов.
  • Считать, что .o — готовая программа.

Пример

gcc -E main.c -o main.i    # препроцессор
gcc -S main.i -o main.s    # компилятор
gcc -c main.s -o main.o    # ассемблер
gcc main.o -o program      # линковщик

ТЕМА 6. Стековая машина

Теория

  • Стек — структура LIFO (последним пришёл — первым вышел).
  • Операции: push (положить), pop (снять).
  • Арифметика: снять два операнда, выполнить операцию, положить результат.
  • Пример: push 4; push 7; add → на стеке 11.

Типовые вопросы

  • Кладут 4 и 7, заменяют суммой. Что сверху? → 11.
  • Кладут 10, 3, вычитают. Что сверху? → 7 (10 − 3).
  • Кладут 2, 5, умножают. Что сверху? → 10.

Ловушки

  • Перепутать порядок операндов при вычитании.
  • Забыть, что сумма заменяет два элемента одним.

Пример

push 4    ; стек: [4]
push 7    ; стек: [4, 7]
add       ; стек: [11]

ТЕМА 7. Аргументы командной строки

Теория

  • argc — число аргументов (включая имя программы).
  • argv — массив строк.
  • argv[0] — имя программы.
  • argv[1], argv[2], … — содержательные аргументы.
  • Все аргументы — строки, даже если выглядят как числа.
  • Программа сама должна преобразовать строку в число (atoi, strtol).

Типовые вопросы

  • ./meter -q 8. Первый аргумент? → -q, строка.
  • ./program --size 12 "two words". Аргументы? → --size, 12, two words — все строки.
  • Сколько аргументов у ./prog a b c? → argc = 4 (имя + 3).

Ловушки

  • Считать, что 8 — число. Нет, это строка "8".
  • Путать argv[0] (имя программы) и argv[1] (первый содержательный).
  • Забыть, что argc включает имя программы.

Пример

int main(int argc, char *argv[]) {
    // argc = 3
    // argv[0] = "./meter"
    // argv[1] = "-q"
    // argv[2] = "8"
    int n = atoi(argv[2]);  // преобразование строки в число
}

ТЕМА 8. Линковка и объектные файлы

Теория

  • .o — объектный файл, результат ассемблирования. Ещё не готовая программа.
  • Линковщик соединяет несколько .o и библиотеки.
  • gcc main.o stats.o -o meter — линковка, результат meter.
  • .o файлы остаются на диске после линковки.
  • Ошибка undefined reference — не передан нужный .o или библиотека.

Типовые вопросы

  • gcc main.o stats.o -o meter. Какой файл исполняемый? → meter.
  • Что с .o файлами? → Остаются на диске, не удаляются.
  • Что делает линковщик? → Соединяет объектные файлы и библиотеки.
  • nm main.o показывает U sum — что это? → Неопределённая ссылка, нужен sum.o.

Ловушки

  • Думать, что .o — готовая программа.
  • Считать, что линковщик удаляет .o.
  • Путать -c (создать .o) и -o (задать имя результата).

Пример

gcc -c main.c -o main.o     # объектный файл
gcc -c sum.c -o sum.o       # объектный файл
gcc main.o sum.o -o program # линковка
# main.o и sum.o остались на диске

ТЕМА 9. Git

Теория

Три области:

  1. Рабочий каталог — текущие файлы.
  2. Индекс (staging area) — что войдёт в следующий коммит.
  3. Репозиторий — история коммитов.

Команды:

  • git init — создать репозиторий.
  • git status — состояние.
  • git add file — записать в индекс.
  • git commit -m "..." — создать коммит из индекса.
  • git diff — изменения рабочего файла относительно индекса.
  • git diff --cached — изменения индекса относительно последнего коммита.
  • git log --oneline — история.
  • git restore file — вернуть из индекса (уничтожает правки).
  • git rm --cached file — убрать из индекса, оставить на диске.
  • .gitignore — шаблоны игнорирования.

Типовые вопросы

  • Незакоммиченная правка в notes.txt. Как посмотреть? → git diff notes.txt.
  • Как записать в индекс? → git add notes.txt.
  • Чем git diff отличается от git diff --cached? → Первый — рабочий файл vs индекс; второй — индекс vs последний коммит.
  • Что делает git rm --cached? → Убирает из индекса, оставляет на диске.
  • Что делает git restore? → Возвращает рабочую версию из индекса, уничтожает правки.

Ловушки

  • Путать add и commit. add → индекс, commit → история.
  • Считать, что .gitignore удаляет файлы. Нет, только игнорирует.
  • Думать, что git restore сохраняет правки. Нет, уничтожает.

Пример

git diff notes.txt        # посмотреть правку
git add notes.txt         # записать в индекс
git diff --cached         # проверить, что в индексе
git commit -m "Update"    # создать коммит
git log -1 --oneline      # посмотреть коммит

ТЕМА 10. GDB

Теория

  • break file:line — точка останова.
  • run — запуск.
  • next — выполнить строку, не заходя в функции, остановиться на следующей.
  • step — зайти внутрь функции.
  • finish — завершить текущую функцию.
  • print expr — значение выражения.
  • watch var — остановка при изменении.
  • display var — показывать значение при остановках.
  • backtrace — стек вызовов.
  • frame n — выбрать кадр.
  • x/8xb &var — 8 байт в hex.
  • continue — продолжить.
  • quit — выход.

Типовые вопросы

  • Выполнить строку и остановиться на следующей? → next.
  • Зайти внутрь функции? → step.
  • Завершить функцию? → finish.
  • Остановиться при изменении переменной? → watch.
  • Показать стек вызовов? → backtrace.
  • Прочитать 8 байт памяти? → x/8xb &var.

Ловушки

  • Путать next и step.
  • Читать неинициализированную переменную.
  • Пытаться читать локальную переменную после завершения функции.

Пример

(gdb) break demo.c:6
(gdb) run
(gdb) next
(gdb) print product
(gdb) continue

ТЕМА 11. Коды возврата и процессы

Теория

  • return 0 в main — успех.
  • Ненулевой код — ошибка/иной исход.
  • echo $? — код завершения последней команды.
  • $? меняется после следующей команды.
  • fork() — создаёт дочерний процесс.
  • waitpid() — родитель ждёт и получает статус ребёнка.
  • Код ребёнка доступен родителю через waitpid, а не через $?.
  • $? показывает код родителя, а не ребёнка.

Типовые вопросы

  • Ребёнок завершился с 7, родитель — с 0. Что покажет echo $?? → 0.
  • Где код ребёнка? → Внутри родителя, через waitpid.
  • Что означает код 0? → Успех.
  • Что означает ненулевой код? → Ошибка/иной исход.

Ловушки

  • Думать, что $? показывает код ребёнка.
  • Забыть, что $? меняется после следующей команды.
  • Путать статус программы и статус дочернего процесса.

Пример

pid_t pid = fork();
if (pid == 0) {
    exit(7);  // ребёнок
} else {
    int status;
    waitpid(pid, &status, 0);
    // WEXITSTATUS(status) == 7
    return 0;  // родитель
}
// echo $? покажет 0 (код родителя)

ТЕМА 12. BIOS, прерывания, диски

Теория

  • BIOS после сброса CPU: CS:IP = 0xF000:0xFFF0 → физический 0xFFFF0.
  • BIOS читает первый сектор по 0000:7C00.
  • Загрузчик читает остальные секторы в 1000:0000.
  • INT 13h — дисковые сервисы:
    • AH=02h — чтение CHS.
    • AH=03h — запись CHS.
    • AH=42h — чтение LBA через DAP.
    • AH=43h — запись LBA через DAP.
  • DL=00h — дискета, DL=80h — первый HDD.
  • CF=0 — успех, CF=1 — ошибка.
  • LBA → смещение: LBA × 512.
  • LBA 3: первый байт 1536 = 0x600, последний 2047 = 0x7FF.
  • Сектор 512 байт.

Типовые вопросы

  • Куда BIOS читает загрузочный сектор? → 0000:7C00.
  • Куда загрузчик читает журнал? → 1000:0000.
  • LBA 3: смещение первого байта? → 0x600.
  • LBA 3: смещение последнего байта? → 0x7FF.
  • LBA 4: первый байт? → 4×512 = 2048 = 0x800.
  • Флаг ошибки после INT 13h? → CF=1.

Ловушки

  • Путать 0000:7C00 (загрузочный сектор) и 1000:0000 (буфер журнала).
  • Забыть, что LBA нумеруется с нуля.
  • Считать последний байт как LBA × 512, а не LBA × 512 + 511.
  • Путать CF и ZF.

Пример

LBA 3, сектор 512 байт:
  первый байт: 3 × 512 = 1536 = 0x600
  последний:   1536 + 511 = 2047 = 0x7FF

ТЕМА 13. INT vs IRQ

Теория

  • INT — программное прерывание, инициирует программа.
  • IRQ — аппаратное прерывание, инициирует устройство.
  • INT 10h — видео, INT 13h — диск, INT 16h — клавиатура BIOS.
  • IRQ1 → INT 09h — клавиатура PS/2.
  • IVT — таблица векторов, 4 байта на вектор, по адресу 0000:0000.
  • Вектор 09h — по смещению 9 × 4 = 36 = 0x24.
  • После IRQ1 нужно послать EOI в PIC (out 0x20, 0x20).

Типовые вопросы

  • Чем INT отличается от IRQ? → INT инициирует программа, IRQ — устройство.
  • Куда переходит CPU по IRQ1? → IVT[09h] → обработчик.
  • Что такое EOI? → Подтверждение завершения прерывания для PIC.
  • Что будет, если забыть EOI? → PIC заблокирует следующие прерывания.

Ловушки

  • Думать, что INT 16h — аппаратное прерывание. Нет, программное.
  • Путать INT 09h (IRQ1) и INT 16h (BIOS-клавиатура).
  • Забыть EOI.

Пример

irq1:
    push ax
    push ds
    in al, 0x60      ; читать скан-код
    ; ... очередь ...
    mov al, 0x20
    out 0x20, al     ; EOI
    pop ds
    pop ax
    iret

ТЕМА 14. VGA

Теория

  • Видеопамять: B800:0000 = 0xB8000.
  • Одна позиция = 2 байта: символ + атрибут.
  • Формула: offset = 160 × row + 2 × col.
  • Атрибут: 16 × фон + цвет.
  • Бит 7 — мигание, биты 6–4 — фон, биты 3–0 — символ.
  • Цвета: 0 — чёрный, 1 — синий, 2 — зелёный, 4 — красный, 7 — светло-серый, A — ярко-зелёный, E — жёлтый, F — белый.
  • stosw пишет AX в ES:DI, DI += 2.
  • lodsb читает из DS:SI в AL, SI += 1.

Типовые вопросы

  • Смещение для строки 3, столбца 10? → 160×3 + 2×10 = 500.
  • Атрибут «жёлтый на синем»? → 16×1 + 14 = 30 = 0x1E.
  • Атрибут «белый на красном»? → 16×4 + 15 = 79 = 0x4F.
  • Атрибут «ярко-зелёный на чёрном»? → 16×0 + 10 = 0x0A.

Ловушки

  • Путать BX = 256×row + col (для BIOS) и offset = 160×row + 2×col (для VGA).
  • Забыть, что строка и столбец с нуля.
  • Путать ASCII-код и числовое значение.

Пример

mov ax, 0xb800
mov es, ax
mov di, 160*2 + 2*5   ; строка 2, столбец 5
mov al, 'A'
mov ah, 0x0A          ; ярко-зелёный на чёрном
stosw

ТЕМА 15. Массив оценок и среднее

Теория

  • Массив 16×4 = 64 байта.
  • Адрес grade[i][j] = grades + 4i + j.
  • FFh — «не выставлена», 00h — выставленный ноль.
  • Среднее только по выставленным: sum / n.
  • Сотые без float: (100 × sum + n/2) / n, только при n > 0.
  • При n = 0 — нет среднего, деление пропускается.

Типовые вопросы

  • Смещение grade[4][2]? → 4×4 + 2 = 18 = 0x12.
  • Оценки 0, 1, 1, FF. Среднее? → (100×2 + 1) / 3 = 67 сотых = 0.67.
  • При n = 0? → Нет среднего.

Ловушки

  • Включать FFh в сумму.
  • Забыть, что 00h — допустимая оценка.
  • Делить на 4 вместо n (числа выставленных).

Пример

Оценки: 00 0A FF FF
sum = 0 + 10 = 10
n = 2
среднее = 10/2 = 5.00
сотые = (100×10 + 1) / 2 = 1001/2 = 500

ТЕМА 16. Сектор GR16

Теория

  • Байты 0–3: GR16.
  • Байты 4–7: версия 1, 16 студентов, 4 работы.
  • Байты 8–71: 64 оценки.
  • Байты 72–73: контрольная сумма байтов 0–71.
  • Байты 74–511: нули.
  • Читается с LBA 1 через INT 13h.
  • Перед заменой RAM: проверка сигнатуры, версии, суммы, диапазонов.

Типовые вопросы

  • Где сигнатура? → Байты 0–3.
  • Где оценки? → Байты 8–71.
  • Где контрольная сумма? → Байты 72–73.
  • Размер сектора? → 512 байт.

Ловушки

  • Путать смещения полей.
  • Забыть про контрольную сумму.
  • Считать, что сектор 1024 байта.

ТЕМА 17. Очередь событий

Теория

  • Кольцевая очередь в RAM.
  • qhead — куда пишет обработчик.
  • qtail — откуда читает основной цикл.
  • Пусто: qhead == qtail.
  • Полно: следующая позиция qhead == qtail.
  • 64 позиции → максимум 63 события.
  • Обработчик IRQ1 не рисует экран, только кладёт в очередь.
  • Основной цикл забирает и обрабатывает.

Типовые вопросы

  • Сколько событий вмещает очередь? → 63 (одна позиция резервируется).
  • Когда очередь пуста? → qhead == qtail.
  • Что делает обработчик? → Читает порт 60h, кладёт в очередь, EOI, iret.

Ловушки

  • Думать, что 64 позиции = 64 события.
  • Путать qhead и qtail.
  • Считать, что обработчик рисует экран.

ТЕМА 18. Real mode и адресация

Теория

  • physical = 16 × segment + offset.
  • 1000:0006 → 0x10006.
  • B800:0000 → 0xB8000.
  • 0000:7C00 → 0x7C00.
  • F000:FFF0 → 0xFFFF0.
  • Сегментные регистры: CS, DS, SS, ES.
  • CS:IP — код, DS:SI — данные, SS:SP — стек, ES:DI — назначение.
  • Сегментный регистр нельзя загрузить immediate.

Типовые вопросы

  • Физический адрес 1000:0006? → 0x10006.
  • Физический адрес B800:0000? → 0xB8000.
  • Формула? → 16 × segment + offset.

Ловушки

  • Забыть умножить сегмент на 16.
  • Путать сегмент и смещение.
  • Пытаться загрузить ES immediate.

ТЕМА 19. NASM-директивы

Теория

  • bits 16 — 16-битный код.
  • org 0x7C00 — начальный адрес.
  • db, dw, dd, dq — 1/2/4/8 байт.
  • times — повторение.
  • equ — константа.
  • times 510 - ($ - $$) db 0 — дополнить до 510 байт.
  • dw 0xAA55 — сигнатура загрузочного сектора.
  • Директивы — для ассемблера, не для CPU.

Типовые вопросы

  • Что такое директива? → Указание ассемблеру.
  • Чем отличается от инструкции? → Инструкция для CPU, директива для ассемблера.
  • Что делает times? → Повторяет.

Ловушки

  • Думать, что директива выполняется CPU.
  • Путать db и dw.

ТЕМА 20. COM1 и PS/2

Теория

  • PS/2 — клавиатура, порты 60h (данные) и 64h (статус), IRQ1 → INT 09h.
  • COM1 — последовательный порт, 0x3F8 (данные), 0x3FD (статус), диагностика.
  • В QEMU: -serial stdio → COM1 в терминал.
  • COM1: BOOT STAGE, READY, SAVED, LOADED, BAD_CHECKSUM, NO_DISK.
  • PS/2: скан-коды, A=0x1E, 0=0x0B, Backspace=0x0E.

Типовые вопросы

  • Порты PS/2? → 60h, 64h.
  • Адрес COM1? → 0x3F8.
  • Куда идёт SAVED? → COM1.
  • Скан-код A? → 0x1E.

Ловушки

  • Путать PS/2 и COM1.
  • Считать, что SAVED идёт на VGA.
  • Путать порты 60h и 0x3F8.
